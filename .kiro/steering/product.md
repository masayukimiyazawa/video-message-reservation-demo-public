# Product Overview

Vonage Video API を用いた「予約機能付きビデオ通話」アプリケーション。エンドユーザーは **WhatsApp 上のチャットボットだけで** 通話予約を行い、予約時刻になると WhatsApp 通知と管理者 UI の画面通知の**両方**を受け取る。管理者・スタッフは RBAC で保護された管理者 UI から予約管理・通話・録画・話者分離文字起こしを操作する。

**対象ユーザー（3 種）**

| ユーザー | 役割 | 到達経路 |
| --- | --- | --- |
| エンドユーザー | 予約・通話参加 | WhatsApp（アプリ不要） |
| スタッフ | 割り当てられた予約の通話・録画のみ | 管理者 UI（ログイン必須） |
| 管理者 | 全予約・録画・文字起こし・権限管理 | 管理者 UI（ログイン必須） |

参照ドメインは **遠隔診療（telemedicine）**。対象サービスに `telemedicine` を含み、通話画面の背景スキンとして「病院遠隔診療テーマ」が必須要件である。

## Core Capabilities

1. **WhatsApp チャットボット予約** — 専用アプリ不要。リッチメディア（リプライボタン / リスト / メディアテンプレート / カルーセル）による会話フローで予約を確定する。
2. **予約の永続化と空き判定** — 外部 MongoDB Atlas に保存し、**重複時は代替日時の選択肢を必ず提示**する（単なるエラー通知にしない）。
3. **予約時刻の二系統通知** — WhatsApp メッセージと管理者 UI の画面通知。**片方の失敗でも他方を止めない**（部分失敗許容）。
4. **レスポンシブビデオ通話** — スマートフォン / PC 双方に対応。背景スキンを複数から選択可能（telemedicine は必須）。
5. **録画と話者分離文字起こし** — 管理者が録画を制御し、録画後に**話者（ストリーム）単位**で整理された文字起こしを取得する。

## Target Use Cases

- アプリをインストールせずに、WhatsApp 上で通話予約を完了させる
- 希望枠が埋まっている場合に、代替枠をその場で提示されて選ぶ
- 予約時刻に「ユーザーへの WhatsApp」＋「管理者への画面通知」で二重に気付く
- スマホ（未ログインのゲスト）でも PC でも通話に参加する
- 管理者が通話中に録画を開始 / 停止し、録画状態をリアルタイムに把握する
- 通話後に「誰が何を言ったか」を話者別に確認する
- 担当者（スタッフ）に予約を委任し、担当範囲外は操作できないようにする
- 英語 / 日本語のどちらの利用者でも同じ機能を操作できる

## Value Proposition

**予約の摩擦を排除すること**が本製品の中心的な主張である。予約の入口を「既にアプリがある WhatsApp」の中に置き、Web フォームやアプリの DL を要求しない。加えて以下を差別化要因とする。

- **会話が純粋な状態機械としてモデル化される** — `nextStep(state, input)` という副作用のない関数であり、顧客接点全体をプロパティテストで検証できる。
- **行き止まりを作らない** — 枠衝突は「代替を提示する」という第一級の導線として扱う。
- **多重化された通知** — 管理者通知は WhatsApp 通知とは独立した経路であり、WhatsApp 側の障害で運用者が気づかなくなることを、要件として保証している。
- **能力境界を正直に扱う文字起こし** — 「話者分離」の実体を channel / stream 単位に限定し、1 ストリーム内の複数話者分離（speaker diarization）は Vonage 純正機能の範囲外として明示的にスコープアウトしている。
- **運用体制に沿った 2 段階 RBAC** — 管理者と「割り当てられたスタッフ」を分けることで、委任しても予約総簿を過剰に公開しない。

## Domain Glossary

| 用語 | 意味 |
| --- | --- |
| 予約時刻 | 予約レコードに保持される開始日時 |
| 対象サービス | 予約対象の種別。`consultation` / `follow_up` / `telemedicine` |
| 対応言語 | `en`（英語）/ `ja`（日本語）のみ。**予約レコードに保存**され、外向き WhatsApp メッセージの言語を決める |
| 背景スキン | 通話画面に適用するテーマ。`default` / `telemedicine` / `office` / `nature` |
| 予約ステータス | `pending` → `confirmed` → `cancelled` / `completed`（クローズド集合） |
| archive（アーカイブ） | Vonage の録画オブジェクト |
| individual stream archive | 参加者ストリームごとに 1 つの録画。`outputMode: "individual"`。**文字起こしはこれでのみ利用可能** |
| channel / channels_metadata | 文字起こし JSON で話者を解決するための単位。`segments[].channel` → `channels_metadata[].id`（＝ストリーム ID） |
| Post-Call Transcription | Vonage 純正の文字起こし。本アプリ独自の STT は持たない |
| ゲストトークン | 有効な予約が 1 件以上存在するセッションに対してのみ発行される、未認証の通話参加トークン |

## Scope Boundaries

**明示的にスコープアウト**

- **speaker diarization**（1 ストリーム内の複数話者分離）— Vonage 純正 Post-Call Transcription の範囲外。バグではなく境界。
- **Video API の Webhook / コールバック受信** — Video 機能はサーバ側 SDK の戻り値とポーリングで完結する。Webhook を受けるのは Messages API のみ。将来対応は webhook ルートの追加で可能。
- **composed archive での文字起こし** — 利用不可。文字起こしを伴う録画は `outputMode: 'individual'` が不変条件。
- **独自 STT / 独自話者識別** — すべて Vonage 純正機能の枠内に留める。

**データ・セキュリティに関する固定制約**

- 予約データは**アプリケーションから独立した**外部 MongoDB Atlas に保持する。
- 外部入力は信頼できないものとして検証・サニタイズする（fail-closed）。Webhook は JWT / 署名検証で改ざん・なりすましを防ぐ。署名は SHA-256 HMAC 必須。
- 所有者を解決できない場合は「所有者とみなさず」拒否する（fail-closed）。

**検証方針の境界**

- 外部サービス挙動の網羅は目的とせず、代表例 1〜3 件で統合テストする。
- レスポンシブ表示と背景スキンは property test の対象外。スナップショットテストと目視確認で検証する。

## UX / Accessibility Expectations

- **バイリンガル対応は UI だけの話ではない。** 管理者 UI・通話 UI・**外向き WhatsApp メッセージ**のすべてが、選択された言語に追従する。日付表示もローカライズし、**UTC で計算**して予約時刻とのずれを防ぐ。
- **レスポンシブは要件**（PC / スマートフォン双方）。ただし CSS flex / grid とメディアクエリで実現し、JS によるレイアウト制御は行わない。
- **失敗時は必ず回復手段を提示する。** 接続失敗 → メッセージ +「再接続」操作。録画失敗・文字起こし失敗 → 状態を記録し、管理者 UI に通知する。録画状態は画面上で常時可視。
- **アイコンのみのボタンには `aria-label` を必ず付与する。** 状態に応じてラベルを切り替える（例: 共有中 → `call.shareStop`）。
- **テストはアクセシブルな role / name でクエリする**（`getByRole('button', { name: 'Reconnect' })`）。data-testid を優先しない。UI 側に `role="status"` / `aria-label` / `aria-current` が必要なのはこのため。
- 権限差は UI 上でも事前に明示する（例:「自身に割り当てられた予約のみ管理できます。」「権限管理は管理者のみが利用できます。」）。
- 画面共有時は権限に応じたレイアウト差を出す（管理者 = 自分の publisher プレビュー、非管理者 = 共有資料を大表示 + 顔は PiP）。

**注意**: 仕様書に WCAG / キーボードナビゲーション / フォーカス管理の明文化された要件は無い。上記は「規約として実装されている実践」であり、標準を新たに制定したものではない。
